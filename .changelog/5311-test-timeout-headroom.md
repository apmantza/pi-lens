- **CI flags the tests that already spent most of their timeout.** `scripts/check-test-timeout-headroom.mjs` reads each shard's `vitest-results.json`, folds the effective per-test budget out of the source (the `it`/`test` value, an options object's `timeout`, the enclosing `describe` or `test.each` tail options, a module-scope `vi.setConfig`, `scaledTestTimeout`, or Vitest's default), and annotates every assertion that ran past 60% of it. A cap the fold cannot settle — a `vi.setConfig` inside a hook or test body, an options name re-bound with `=`, an options object with a spread after `timeout` — is counted in the summary as unresolved and measured against the smallest budget the file declares, so it is visible rather than measured against a default it does not run under. The step is advisory (`continue-on-error`) and a run that could not measure at all emits a `::warning` rather than reddening the shard, `scripts/test-timeout-headroom-baseline.json` carries the current offenders, so the annotation surface is the new ones. (`--fail-on-new` makes the same check block.) A baseline row whose test has been renamed or deleted is printed as `stale` so the ledger cannot quietly stop measuring. (refs #5311)
