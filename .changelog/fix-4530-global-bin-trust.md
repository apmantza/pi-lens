- **Global binary lookups honour project trust (closes #4530)** — Until pi marks a project trusted, installer and LSP lookups and their child environments exclude PATH entries inside the project, including directory symlinks, and project configuration no longer changes where the global lookups look. Each ignored lookup dir is recorded once per session, and the trust notice is emitted once per session with how to trust the project. Availability checks and archive extractors use the same scoped PATH. A compiler lookup with an executable compiler file in a refused PATH entry emits only the trust notice; a genuinely missing compiler still emits the resolution notice. Trusted projects and MCP hosts resolve tools as before. Binary discovery also accepts only regular files as command candidates, and only executables on POSIX, so a directory or non-executable file can no longer shadow the real binary; interpreter-launched scripts stay accepted through the file-only check. A child whose scoped PATH loses every entry now gets no PATH at all, because an empty PATH (or an empty entry) makes the kernel search the child's own working directory; the same rule applies to every PATH pi-lens composes. A link in a global bin directory whose target lives in the project is refused, and the pip private-prefix rung resolves its interpreter through the scoped PATH. Discovered commands, including Windows npm shim script targets, are judged against the caller’s project root. POSIX child environments preserve the distinction between PATH and Path. Availability verdicts are keyed by trust and caller root, so trusting a project mid-session re-probes instead of keeping the earlier answer.
