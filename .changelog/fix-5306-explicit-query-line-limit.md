section: Changed
audience: user
---

- **A large file can now be checked with `lens_diagnostics source=lsp` on one path (refs #5306)** — the new user-level config key `lsp.queryMaxFileLines` (whole number, 5000 to 40000, suggested 20000) raises the line limit of the explicit single-file query only; per-edit sync, dispatch and batch queries keep 5000 lines and 2 MiB (a batch's 20 s pre-sweep warm-up still opens a file past that bound, and the workspace sweep never checked it; both are named residuals). A project `.pi-lens.json` cannot set it (ignored, one global-only warning per session), no tool argument can raise it, and an out-of-range value is ignored with a warning. On that same single-file query an explicit `waitMs` now sets the wait past the language server's per-server wait (clangd's 1500 ms), up to 30000 ms, and a shorter one never shortens it; before, `waitMs=120000` still timed out at about 1.5 s. A file over the limit or a wait that runs out is reported as too large or timed out, never as clean, and the timeout text no longer tells the model to "increase waitMs" where that could not help. On every LSP check (per-edit, dispatch, batch and query), a language server whose wait ran out, or whose pull failed, now reads as timed out even when a slower scanner such as opengrep was still running; before, it read as clean. A server that stays silent on a clean file (TypeScript, Markdown, Lua) still reads as clean.
